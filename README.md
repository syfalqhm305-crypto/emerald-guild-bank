# بنك النقابة (Emerald Guild Bank)

موقع بنك افتراضي لنقابة واتساب: واجهة تعريفية + بنك (رصيد، تحويلات، سجل عمليات، مستويات) + متجر يخصم تلقائياً من رصيد العضو. **الواجهة الأمامية ثابتة (HTML/CSS/JS بدون أي إطار عمل) والباك-إند سيرفر Node.js/Express حقيقي متصل بقاعدة بيانات SQLite حقيقية.**

## هيكل المشروع

```
index.html            ← الصفحة الرئيسية (الواجهة التعريفية + التطبيق)
css/style.css          ← كل التصميم
js/icons.js            ← أيقونات SVG بسيطة (بدون إيموجي)
js/api.js              ← طبقة الاتصال بالخادم (fetch)
js/app.js              ← منطق التطبيق كامل (كل الصفحات)
server/
  server.js            ← خادم Express + كل نقاط الـ API
  db.js                 ← الاتصال بقاعدة بيانات SQLite + إنشاء الجداول + بيانات تجريبية أولية
  package.json
  .env.example
```

## التشغيل محلياً

يتطلب Node.js (نسخة 18 أو أحدث). داخل مجلد `server`:

```bash
cd server
npm install
npm start
```

بعدها افتح المتصفح على: `http://localhost:3000`

الخادم يعرض الواجهة الأمامية (index.html, css, js) **ونقاط الـ API** من نفس المنفذ، فلا تحتاج تهيئة إضافية محلياً.

عند أول تشغيل يتم إنشاء ملف `server/guild.db` (قاعدة بيانات SQLite حقيقية) تلقائياً، مع بيانات تجريبية (أعضاء وهميون، متجر، عمليات) يمكنك تعديلها أو حذفها بالكامل لاحقاً من داخل الموقع (الإعدادات ← إعادة تعيين البيانات) أو مباشرة من قاعدة البيانات.

## النشر (Deployment)

### الخيار الأبسط: خدمة واحدة تستضيف كل شيء
ارفع مجلد المشروع بالكامل إلى منصة تدعم Node.js مثل **Render** أو **Railway** أو **Fly.io**:
- Build command: `npm install --prefix server`
- Start command: `npm start --prefix server` (أو `node server/server.js`)
- تأكد أن للخدمة **قرص تخزين دائم (persistent disk)** لأن SQLite ملف فعلي؛ بدون ذلك ستُحذف البيانات عند كل إعادة نشر. Render وRailway يوفران هذا كخيار (Persistent Disk / Volume).

بعد النشر، رابط الخدمة نفسه هو موقعك الكامل (الواجهة + API من نفس الدومين) — لا حاجة لتعديل أي شيء في `js/api.js`.

### الخيار الثاني: استضافة الواجهة الأمامية بشكل منفصل
لو حبيت تستضيف `index.html` و`css/` و`js/` على GitHub Pages أو Netlify منفصلة عن الباك-إند:
1. انشر مجلد `server` وحده على Render/Railway (نفس الخطوات أعلاه).
2. افتح `js/api.js` وغيّر السطر:
   ```js
   const API_BASE = '';
   ```
   إلى رابط الباك-إند المنشور، مثال:
   ```js
   const API_BASE = 'https://your-backend.onrender.com';
   ```
3. تأكد أن CORS مفعّل (هو مفعّل افتراضياً في `server.js` عبر حزمة `cors`).

### استبدال SQLite بقاعدة بيانات أخرى (MySQL / PostgreSQL / MongoDB...)
كل استعلامات قاعدة البيانات معزولة داخل `server/db.js` ونقاط الـ API في `server/server.js`. إذا تبي تربطها بقاعدة بيانات عندك جاهزة (مثلاً MySQL على استضافتك، أو Supabase/PlanetScale/MongoDB Atlas):
- استبدل محتوى `db.js` بمنطق الاتصال بقاعدتك (نفس أسماء الجداول/الحقول أو عدّل الاستعلامات في `server.js` لتطابق قاعدتك).
- الواجهة الأمامية (`js/api.js` و`js/app.js`) لن تحتاج أي تعديل لأنها تتكلم فقط مع نقاط `/api/...` بغض النظر عن قاعدة البيانات خلفها.

## نقاط الـ API المتاحة

| Method | Path | الوظيفة |
|---|---|---|
| GET | `/api/state` | جلب كل بيانات النقابة (المعلومات، القادة، الأعضاء، المتجر، العمليات) |
| PUT | `/api/info` | تعديل بيانات النقابة/البنك |
| POST | `/api/leaders` | إضافة قائد |
| DELETE | `/api/leaders/:id` | حذف قائد |
| POST | `/api/members` | إضافة عضو |
| POST | `/api/members/:id/adjust` | إضافة/خصم رصيد عضو (`{type:'in'|'out', amount, reason}`) |
| POST | `/api/store` | إضافة منتج للمتجر |
| DELETE | `/api/store/:id` | حذف منتج |
| POST | `/api/store/purchase` | شراء (خصم تلقائي من الرصيد) — `{memberId, items:[{id,qty}]}` |
| POST | `/api/transfer` | تحويل رصيد بين عضوين — `{fromId, toId, amount, note}` |
| POST | `/api/prizes` | منح جائزة مسابقة |
| POST | `/api/reset` | إعادة تعيين كل البيانات للوضع الافتراضي |

كل عملية تُنشئ صف عملية (transaction) في قاعدة البيانات وتُحدّث الرصيد فعلياً — هذا بنك حقيقي من ناحية آلية العمل، بمعنى أن الأرصدة والعمليات محفوظة بشكل دائم في SQLite.

## ⚠️ ملاحظة أمان مهمة

هذا المشروع **بدون نظام تسجيل دخول حقيقي (بدون كلمات مرور)** — أي شخص يفتح الموقع يختار "الدخول كـ" أي عضو من القائمة، بدون تحقق. هذا مناسب لمجموعة واتساب صغيرة موثوقة فيما بينها، **وليس مناسباً كبنك حقيقي فيه فلوس فعلية**. قبل أي استخدام جاد، ينصح بإضافة:
- تسجيل دخول حقيقي (بريد/كلمة مرور أو OTP عبر واتساب) بدل اختيار الاسم من القائمة.
- صلاحيات محمية على مستوى السيرفر (حالياً أي شخص يعرف رابط الـ API يقدر يستدعي أي endpoint مباشرة).
- HTTPS إجباري عند النشر (المنصات المذكورة أعلاه توفره تلقائياً).

إذا تحب أساعدك تضيف نظام تسجيل دخول حقيقي (JWT + كلمات مرور مشفّرة)، قولّي وأجهزه لك.
